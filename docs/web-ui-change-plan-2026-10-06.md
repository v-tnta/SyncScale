# SyncScale Web UI変更計画

作成日：2026-10-06。状態：計画作成済み／本体の実装は未着手。

## 1. 方針と優先順位

A案の落ち着いた外観を採用する。ユーザーが指定した配置・表示変更を反映し、それ以外の業務ロジックと操作フローは現行実装を優先する。モックアップは見た目と構成の参照資料であり、その仮データ・独自の遷移・タイマー・状態管理を本体にコピーしない。

設計の判断順は、今回の明示的な要望、現行実装の機能・操作、既存設計書、モックアップの順とする。既存のReact、Tailwind CSS、Radix Dialog、react-big-calendar、Lucideを活用する。研究同意、認証、課題同期、記録、分析計算をデザイン変更に伴って再実装しない。

対象はReact製Web版とその公開ページ。Flutter製モバイル版・Chrome拡張機能そのもののUIは今回の実装範囲に含めない。Webの同期受け口・拡張機能案内は対象。

## 2. 確定した変更内容

| 領域 | 変更内容 |
|---|---|
| ブランド | 現行 `web/src/assets/logo.png` を使用する |
| 外観 | ライト／ダーク切り替え。文字・背景・境界・入力・モーダル・通知を統一 |
| ホーム | 課題一覧を左上、締切カレンダーを右に配置。「取り組む課題」は作らない |
| フッター | 最終同期表示と右下のキャッチコピーを表示しない。必要な法務・案内導線は別途維持 |
| 課題追加 | 「課題を追加」を一覧右上に配置。現行入力項目・検証・登録処理を維持 |
| 一覧 | 一覧の行領域を内部スクロールにし、見出し・追加ボタン・完了一覧導線を見失わせない |
| カレンダー | 月／週表示を維持。締切日の数字にS/M/L色の円背景と白文字。今日は薄青の角丸背景。点は作業記録専用 |
| 完了課題 | 完了月別一覧 → 完了課題詳細。詳細はコンディション・メモ・実績チャートを表示し、タイマーは表示しない |
| 分析 | 今月／全期間と既存5項目を維持。項目ごとにカードで区切り、既存のアイコン・色の意味を引き継ぐ |
| ext-sync | 通常のナビに追加しない。既存の自動遷移を維持し、受信待ち・完了に進行ボタンを追加しない。未ログイン時のGoogleログインは維持 |
| 外部リンクのボタン | オンボーディング／研究参加情報のアンケートとChromeウェブストアはホバー時に薄青、LINEは緑 |

「オーバーレイ」はホバーと解釈し、モックには `hover` に加えて `focus-visible` と押下時の表示も反映した。既存のフォーカスリングは消さない。LINEの緑上は読みやすい濃色文字を使用し、薄青は両テーマで読める色の組み合わせを持たせる。これは外部リンクボタンへの指定で、「回答しました」「参加しました」「インストールしました」などの進捗確定ボタンとは分ける。

## 3. 実装手順

### 0. 現状の固定と差分の整理

- 作業ツリーに既存の未コミット変更があるため、開始時に差分を確認し、現在の変更を含む状態を比較基準として記録する。既存ファイルを巻き戻さない。
- ルート・モーダル・チュートリアルの遷移と代表画面を記録する。正常・未ログイン・未同意・0件・読込中・失敗を確認する。
- `npm run lint -w web` と `npm run build -w web` の実行結果を記録し、元からある問題と新規問題を区別する。
- 実装を分離する場合も、未コミット変更を取りこぼした古いベースから始めない。

完了条件：既存変更の扱い、対象画面、既存チェック結果が明確である。

### 1. 共通デザインとテーマ

主な対象：`web/src/index.css`、`web/src/App.jsx`、`web/src/main.jsx`、`web/index.html`。必要に応じてテーマ用フックと小さな共通部品を追加する。

- 背景、面、文字、補足文字、境界、主要操作、警告、S/M/L、作業記録のトークンを定義する。
- 角丸、余白、文字階層、ボタン／入力／リンクの状態を共通化する。用途が違う部品の丸みや密度は役割で区別する。
- ライト／ダーク／端末に合わせるを実装案とし、選択を端末内に保存する。初回の明暗反転を抑え、端末設定の変更は自動モードだけに追従する。
- テーマをアプリの最上位に適用し、Radix Portal、独立ページ、Sonnerの通知にも反映する。
- フォントは現在のNoto Sans JPを継続し、極小の説明文や過剰な太字を整理する。

完了条件：ログイン前後・ページ移動・モーダル開閉・再読込で外観が一貫する。

### 2. ホームと課題一覧

主な対象：`Layout.jsx`、`HomePage.jsx`、`TaskList.jsx`、`TaskForm.jsx`、`SizeLabelSelector.jsx`。

- 現行ロゴを使用し、不要な下部文言を除く。幅の縮小計算に依存する左右指定を、最小幅を持つ明示的なレイアウトに整理する。
- 課題一覧を先頭に配置し、その右上に追加ボタンを置く。フォームを開く方式はモックの一覧内展開を初期案とする。
- 一覧の見出し・操作と、スクロールする行を別領域にする。高さは利用可能な画面高を基準に上限を設定し、長い課題名や件数増加に対応する。
- 0件、すべて完了、読込中、エラーを作り分ける。色に加えてS/M/Lと状態を文字でも示す。
- 追加時のフォーカス移動・キャンセル後の復帰・保存後の見え方を整える。

完了条件：追加・選択・完了・完了一覧を見失わず、20件以上でも周囲の画面が過度に伸びない。

### 3. 月／週カレンダー

主な対象：`Calendar.jsx`、`web/src/index.css`、`web/src/domain/taskSize.js`。

- react-big-calendarと既存イベント生成処理を維持し、日付ヘッダーなどの表示部分を調整する。
- S/M/Lの色相を保持しつつ、白い日付数字を読める濃さを用途別トークンに分ける。既存のサイズバッジや分析色まで一律に暗くしない。
- 今日・選択日・締切・作業記録を別々の状態として実装する。今日と締切が重なる場合は、薄青の角丸背景の中に締切色の円を置く。
- 作業ログの点は月表示で維持し、週表示では既存の時間軸上の作業時間の帯を残す。日付の装飾によって締切時刻・課題名・イベント選択を失わないようにする。
- 同日に複数サイズの締切がある場合は、最新モックの「円の分割色＋日付選択後の課題一覧」を初期案とする。これは明示指定ではなく実装案であり、判読性を比較画面で確認する。
- 完了課題、サイズ未設定、前後月、日跨ぎログ、短いログ、同時刻の課題を扱う。

完了条件：月／週と前後移動・今日への移動が機能し、色変更後も課題と作業時間を識別できる。

### 4. 課題詳細・記録・確認モーダル

主な対象：`Modal.jsx`、`ConfirmModal.jsx`、`TaskOverlay.jsx`、`Timer.jsx`、`GanttChart.jsx`、`CompletedTasksModal.jsx`、`ConditionInputModal.jsx`、`TaskSizeEstimateModal.jsx`、`DateTimePicker.jsx`。

- 共通の面・見出し・閉じる操作・入力・アクション配置に揃える。現在のRadixによるフォーカス制御、重なり順、チュートリアル時の例外を維持する。
- 完了月別の一覧と、その上に開く課題詳細の関係を維持する。詳細を閉じると元の一覧に戻れることを確認する。
- 未完了詳細のタイマー／手動記録、完了詳細のコンディション／メモ、両方の実績チャートを再現する。
- 削除は現行の完全削除確認へ進める。未提出への復帰、編集、提出完了からコンディション入力への遷移を保持する。
- タイマーの開始・停止・再開・記録、作業名未入力時の確認、手動記録の1〜1440分の検証と既定名を保持する。
- 日時ピッカーや計測を、モックの簡易処理で置き換えない。

完了条件：表示の変更前後で、同じ操作から同じ更新処理・確認・復帰先に進む。

### 5. 分析と設定

主な対象：`AnalyticsPanel.jsx`、`SettingsPanel.jsx`、`ConsentWithdrawModal.jsx`、`web/src/content/components.js`。

- 分析は「⏱ 平均着手タイミング」「🎯 サイズ別の平均作業時間」「🌙 一夜漬け度」「🕐 よく作業する時間帯」「🚨 放置タスク」の5カードにする。
- シアン／オレンジ／赤、緑の作業時間、一夜漬け度の暖色を現行から引き継ぎ、ダークでも境界を読み取れるようにする。
- 今月／全期間と、既存の集計対象・計算・空状態・時間帯区分を維持する。モックの固定サンプル値は移植しない。
- 設定の通知、研究参加情報、チュートリアル再実行、ログアウト、二段階の同意撤回を維持する。

完了条件：同一データの集計結果が変わらず、5項目の境目と色の意味が明瞭になる。

### 6. ログイン・研究参加・同期・案内

主な対象：`LoginPage.jsx`、`AgreementPage.jsx`、`OnboardingPage.jsx`、`InfoPage.jsx`、`ExtSyncPage.jsx`、`PrivacyPolicy.jsx`、`MobilePrivacyPolicy.jsx`、`ExtensionGuideModal.jsx`、`MobileAppPromoModal.jsx`。

- 共通のブランド・面・文字・ボタンを適用し、3種の外部リンクのホバー色を両ページで統一する。
- 実際の外部リンク、研究用IDの事前入力、外部リンクを開いた後に進捗確定する制御、Chrome準備案内を保持する。
- 同意書・ポリシー本文・版・研究期間・同意保存のタイミングを変えない。
- ext-syncは受信・ACK・保留データ・ログイン／同意の判定・既存タイムアウト後の遷移を維持し、待機画面だけを整える。模擬的な数秒待機や、受信成功を仮定する処理は導入しない。
- モバイル版への案内やストアバッジは現行素材と実際のリンクを使用する。

完了条件：外部サービスへの導線と同意・同期が、見た目の変更によって途切れない。

### 7. チュートリアル追従と全体確認

主な対象：`DynamicTutorialGuide.jsx`、`Tutorial.jsx`、`web/src/content/tutorialGuide.js`、関連フォーム・モーダル。

- 課題追加フォームの展開に合わせて、ガイド開始時に対象を表示する。対象ID・重なり順・クリック可能領域を確認する。
- 配置変更により不正確になる「右上」などの案内は更新する。15ステップ＋完了場面を通して実行する。
- ガイド外からの通常操作でも、フォーカス・閉じる操作・スクロールが成立することを確認する。
- 実装結果を `docs/systemdesign-v3.md` に反映する。今回作る計画書だけを新たな仕様の正典にしない。

## 4. 検証と完了条件

| 観点 | 確認内容 |
|---|---|
| テーマ | ライト／ダーク／自動、選択保存、初回表示、Portal、通知、公開ページ |
| 外部ボタン | 両ページの3リンクで通常・hover・focus・押下を確認。キーボードでも遷移可能 |
| 一覧 | 0／1／20件以上、長い日本語、内部スクロール、フォーム展開、操作位置維持 |
| カレンダー | 月／週、同日複数サイズ、今日＋締切、色以外の識別、ログの日跨ぎ・重なり、イベント選択 |
| 課題操作 | 追加→見積もり→計測／手動記録→完了→完了詳細→未提出へ戻す、編集・削除確認 |
| モーダル | 入れ子の閉じる順、Esc、背景操作、フォーカス復帰、内容が長い場合 |
| 分析 | 同じデータで改修前後の値が一致、今月／全期間、データなし、5項目、色とアイコン |
| 研究参加 | 新規／既存ユーザー、未同意、各オンボーディング段階、再実行、同意撤回の確認 |
| 同期 | ログイン前後、未同意、受信前後、保留データ、既存タイムアウト経路、重複取り込み防止 |
| サイズ | 主に1024／1280／1440px、200%ズーム。公開ページは狭い画面も確認 |

重要：現行 `main.jsx` は768px以下またはモバイル端末の `/svc/` をFlutter版へリダイレクトする。縮小したReactモックをそのまま本番スマートフォン動作と見なさない。今回この振り分けを変更せず、境界付近の動作を確認する。

各まとまりの実装後に変更箇所の操作確認を行い、最終段階でWebのlint/buildと代表シナリオを実行する。必要な追加テストは、同期遷移・テーマの保存・日付表示の分岐など、壊れると影響のある振る舞いに絞る。装飾クラスの一致だけをテストするコードは増やさない。

本計画時点でブラウザーによるモックの視覚検証は未実施。モックの構文・画面生成の確認を、本番UIの操作検証の代わりにはしない。

## 5. 進め方

順序は **現状固定 → 共通テーマ → ホーム／一覧 → カレンダー → モーダル → 分析／設定 → 公開ページ／同期 → チュートリアルと全体確認**。

変更はこの単位で分けてレビュー可能にする。最初の実装成果物は「テーマ切り替えが全ページに効き、新しい一覧配置で課題操作ができる状態」とする。以後の段階で既存機能を確認しながら適用範囲を広げる。今回の作業成果物は更新したモックと本計画書であり、アプリ本体の変更や公開はまだ行っていない。
